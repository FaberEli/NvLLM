NvLLM 本地常驻推理服务

🧭

👁️

🤖

Router：可选激活 + AutoRouter（0.6.0）

路由不再是启动时记一个旗标，而是一条命令激活的能力。nvllm router on 扫缓存里的决策模型（System One）——识别靠厂商中立的 model_router.yaml 标记（不写死任何本地模型名，NvLLM 是通用后端引擎），没有则告知激活失败 + 下载指引；有则列出让你挑 judge，还可选让已加载的本地大模型读元数据推荐一个。激活落盘（router.json），下次 nvllm serve 起 judge 常驻、模型列表多出 AutoRouter——选它即由常驻 judge 把候选当选项（A/B/C…）打分、读概率分布取 argmax，选到最合适的本地模型。judge 常驻、不计入 --max-models、永不被驱逐。

驻留与回收策略

规则说明
并发驻留--max-models N：同一时刻最多 N 个非 judge 模型常驻；加载串行（spawn+ready 全程持锁），就绪后并发服务。
腾位顺序需要加载新模型时先驱逐已过期（超过 keep-alive），再按 LRU（最近最少使用）。
在途保护inflight > 0 的 worker 永不回收——包括流式输出进行中（流式转发自身持有 inflight 直到流结束）。
Router judge不计入名额、永不驱逐、也不参与腾位。
崩溃处理monitor 定期体检：worker 崩溃 → 标记 errored（后续请求得到明确报错）；空闲过期 → 卸载释放显存。

DGX Spark（GB10）调优要点

128GB 统一内存 worker gpu-memory-utilization 默认 0.5（vLLM 默认 0.92 在 GB10 上会失败） N 模型共存 每个 worker 的占比相对总内存：N×U ≤ 1，如 2 模型 → U≈0.35 JIT 防爆内存 MAX_JOBS=2 限制 FlashInfer 并行编译（默认并发会 OOM-kill nvcc） Python 3.12 vLLM 0.31 仅发 3.10–3.13 wheel，安装脚本自动选 3.12
